---
title: 统计页面
description: 在 opencodex 中查看 5 分钟聚合用量、当前配额周期和按当前价格实时计算的成本。
---

网页控制台在现有 **用量** 页面旁新增独立的 **统计** 页面。两个页面职责不同：原 **用量** 页面保持现状，用于查看日志派生的覆盖率与历史；**统计** 页面使用轻量聚合数据，适合长期查看用量、配额和成本。

## 保存什么数据

统计数据按以下维度聚合：

- 5 分钟时间桶；
- 提供方；
- 隐私安全的账号 / 日志标签；
- 最终解析到的模型。

聚合数据只保存请求数量和 Token 数量，不保存提示词、响应内容、会话文本，也不会再建立一份逐请求历史。

输入 Token 保留提供方上报的总输入，同时单独保留：

- **命中（缓存输入）**；
- **创建（缓存写入）**。

这样既能在一个位置看清三者关系，也不会在总 Token 或成本计算中重复累计缓存 Token。

统计读取会从现有 usage ledger 增量追赶。如果游标已经超出管理接口的有界读取窗口，只会进行一次完整追赶，之后恢复增量读取。

## 自动趋势粒度

趋势图根据所选时间范围自动决定展示粒度：

| 查询范围 | 展示粒度 |
| --- | --- |
| 1 小时以内 | 5 分钟 |
| 超过 1 小时、1 天以内 | 1 小时 |
| 超过 1 天 | 1 天 |

底层最小持久化粒度为 5 分钟，因此页面不会伪造不存在的逐分钟数据。

## 当前配额周期

当上游提供已用百分比和重置边界时，统计页面只展示 **当前周期**：

- 周期开始；
- 周期结束；
- 上游上报的已用百分比；
- 本地在该周期内观察到的 Token 用量；
- 当前周期预计 Token 总量；
- 本地按 API 价格估算的已用金额；
- 当前周期预计金额总量。

已知窗口的周期开始时间由上游重置边界和窗口长度计算。因此如果上游中途改变或重置周期，页面直接显示新的开始 / 结束日期，不额外给它加“临时重置”之类的本地标签。

只有当本地聚合历史覆盖整个当前周期时才计算预计总量：

```text
当前周期预计总量 = 本地已观察用量 / 上游已用比例
```

如果当前周期历史不完整，则不显示总量估算，避免拿残缺历史外推。这个值用于观察额度变化；订阅额度、风控额度不一定与 Token 或 API 标价严格线性对应。

## 价格与成本

统计数据 **不保存价格和成本值**。页面读取数据时，才使用已聚合的 Token 数量和当前价格配置重新计算成本。

**价格配置** 弹窗复用现有 provider 的 `modelCosts` 配置。没有自定义价格时使用项目内置的已验证 / 默认价格；自定义价格按每 100 万 Token 设置四项：

- 输入：总输入扣除缓存命中和缓存创建后的非缓存输入；
- 缓存命中；
- 缓存创建；
- 输出。

删除自定义覆盖后，会重新使用该提供方 / 模型的内置价格解析结果。

和 opencodex 其他页面一致，这些金额只是 API 标价等效估算，用于对账和趋势观察，不是账单，也不能证明订阅提供方实际收取了该金额。
